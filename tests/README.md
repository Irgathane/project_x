# Automated gameplay tests

Drives the real engine with scripted input so gameplay can be checked without a
human at the keyboard. Python generates the input, the engine runs it, Python
asserts on a per-frame trace of the player.

```bash
python3 tests/test_smoke.py            # all tests
python3 tests/test_smoke.py strafe     # tests whose name contains "strafe"
```

## Why it works this way

**No Lua.** QuakeSpasm has no scripting API, and the project is deliberately
vanilla QuakeC with no engine-only extensions. Adding a scripting language to
the engine would be a much bigger change than the need justifies.

**No demo files.** Tempting, because demos look like "recorded input", but
`CL_WriteDemoMessage` (cl_demo.c) stores only the **server→client message
stream** — the `usercmd`s are never written. Playback replays recorded messages
and does not simulate physics, so a demo cannot drive movement or shooting. A
generated demo would test nothing.

**Instead:** a small engine patch injects input and traces state, and Python
owns the scenario. The server, physics and QuakeC are untouched, so tests
exercise the real movement and weapon code paths.

## How it is wired

`tests/engine/test-input.patch` adds `Quake/test_input.c` / `.h` and three hooks:

| Hook | Purpose |
|---|---|
| `CL_BaseMove()` (cl_input.c) | replaces the keyboard-derived usercmd with the next script line; also sets `in_attack` / `in_jump` / `in_impulse` |
| `CL_SendCmd()` (cl_main.c) | writes one CSV row of player state per frame |
| `Host_InitLocal()` (host.c) | registers the harness cvars and parses its command line |

Because `usercmd_t` holds only angles and move speeds, attack/jump/impulse are
driven through the engine's own input state (`in_attack`, `in_jump`,
`in_impulse`) rather than the command structure.

`-test_fps` sets `host_framerate` to a fixed timestep, so one script line is
exactly one frame and runs are comparable.

## Setup (only after re-cloning the engine)

`quakespasm/` is gitignored, so the patch lives in the repo instead:

```bash
cd quakespasm
git apply ../tests/engine/test-input.patch
cd Quake && make USE_SDL2=1 MP3LIB=mpg123 -j2
```

Patch was generated against QuakeSpasm commit `e1c94a0`.

## Input script format

One line per client frame, whitespace separated:

```
<yaw> <pitch> <roll> <forwardmove> <sidemove> <upmove> [buttons] [impulse]
```

`buttons` is a bitfield: `1` = attack, `2` = jump. Blank lines and `#` comments
are skipped. Scripts are generated by `runner.hold()`, `runner.turn()` and
`runner.seconds()`, not written by hand.

## Trace columns

```
frame,time,px,py,pz,vx,vy,vz,yaw,pitch,roll,
health,armor,shells,nails,rockets,cells,weapon,items,flags,onground,waterlevel
```

Rows are written *before* that frame's command is simulated, so the trace lags
the world by one frame.

## Adding a test

```python
def test_my_thing():
    result = run(hold(5) + hold(seconds(1.0), forward=320.0))
    result.assert_no_engine_errors()   # catches Host_Error / PR_GetString
    assert result.peak_horizontal_speed() > 250.0
    return "detail shown on PASS"
```

Then add it to `TESTS` at the bottom of the file.

**Assert on velocity, not distance, where you can.** The starter map is small —
a 1s strafe can hit a wall after ~48 units, which turns a distance assertion
into an accidental map-layout test. `peak_horizontal_speed()` is map-independent.

## Current coverage

Spawn/idle, look (yaw applied, no drift), forward walk, strafe, jump (leaves
ground and lands), shooting (consumes shells), dry fire (ammo never negative),
plus a blanket "no engine errors" check on every run.

## Known limits

- **QuakeSpasm only.** vkQuake is the shipping engine but has no such patch; it
  would need the same hooks applied to its tree. Engine-specific divergence is
  therefore not covered.
- **Listen server only.** The trace reads `sv_player`, which exists only when
  the client is also the server.
- **Not bit-exact.** Fixed `host_framerate` makes runs comparable, but the tests
  assert thresholds rather than exact positions.
- These tests catch "input does nothing", "physics broke", "QuakeC errors on a
  code path". They do not judge whether the game is fun.
